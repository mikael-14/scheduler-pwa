# pwa-scheduler

## Overview
This project is a Vue.js Progressive Web Application (PWA) designed for scheduling tasks. It utilizes Docker for containerization and Vite as the build tool.

## Project Structure
```
pwa-scheduler
├── src
│   ├── main.ts
│   ├── App.vue
├── public
│   ├── img/icons      # app icons (home screen, splash, notifications)
│   ├── .htaccess      # Apache: HTTPS, app routes, security headers (CSP), caching
│   └── push-sw.js     # web push handlers, imported by the generated service worker
├── Dockerfile
├── docker-compose.yml
├── package.json
├── vite.config.js     # also the PWA manifest (name, colours, icons) and service worker
└── README.md
```

## Installing on a phone

The manifest and service worker are generated by `vite-plugin-pwa` (see `vite.config.js`).
The app shows an **"Adicionar ao telemóvel"** button on the login page, in the side menu and in
Settings (`src/components/common/InstallButton.vue`, `src/utils/install.ts`):

- Android (Chrome, Edge, Samsung Internet) and desktop Chrome/Edge: opens the browser's install dialog.
- iPhone / iPad: explains Share → "Add to Home Screen" (Safari has no install dialog). Push
  notifications on iPhone only work once the app is added this way.
- Other mobile browsers: explains where the install option is in the browser menu.
- Hidden when the app already runs installed.

Installing needs **HTTPS** (or `localhost`): on a phone, use the real domain or a tunnel, not the
computer's LAN IP over http. To change the logo, replace the PNGs in `public/img/icons` with the
same sizes (the maskable one keeps the logo inside the middle 80%).

## Getting Started

### Prerequisites
- Docker
- Docker Compose

### Installation
1. Clone the repository:
   ```bash
   git clone <repository-url>
   cd pwa-scheduler
   ```

2. Build the Docker image:
   ```bash
   docker-compose build
   ```

3. Start the application:
   ```bash
   docker-compose up
   ```

### Usage
- Access the application at `http://localhost:5173`.
- The application supports offline functionality and can be installed as a PWA.

### Permissions

The app shows each page and button only to who may use it, from the permissions the API sends
(`GET /api/user`) and each schedule's `can` flags; the API checks everything again. Page guards
are in `src/router/index.ts` (`meta.permissions`). The roles, their permissions and what each page
needs are described in `scheduler-api/README.md` ("Permissions and roles" → "In the PWA").

### Security

- **Headers**: `public/.htaccess` (copied into `dist/`) sets a strict Content-Security-Policy, plus
  HSTS, `nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy` and `Permissions-Policy`. The
  page may only run its own scripts and talk to itself and the API: the build replaces
  `__API_ORIGIN__` with the origin of `VITE_API_URL` (`securityHeaders` plugin in
  `vite.config.js`). A new outside service (fonts, images, scripts, another API) must be added to
  that policy, or the browser blocks it. Nothing is loaded from other sites: the avatars are
  drawn by `UserAvatar.vue`, and the Google / Facebook logos are in `public/img/social`.
- **Email confirmation**: after registering, and after changing the email in the profile, the
  app waits on `/verify-email` (`src/views/VerifyEmail.vue`). That page also opens the link from
  the email, resends it, and lets a mistyped email be corrected. An API answer of 403
  `email_unverified` sends the user there (`src/config/axios.ts`).
- **Notifications** only open pages of the app (`public/push-sw.js`).
- 429 answers (rate limits, see `scheduler-api/README.md` → "Security") show "Demasiados pedidos
  seguidos".
